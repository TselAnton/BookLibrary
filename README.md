# BookLibrary
### Описание
Небольшая программа, исключительно для домашнего использования, 
которая позволяет вести собственную домашнюю книжную библиотеку 
с отслеживанием и аггрегацией имеющихся книг. 

### Сборка
- JDK 17, JavaFX 21.0.12 LTS, Maven; текущая разработка — 5.0.0-SNAPSHOT
- Maven: mvn clean package

Запуск: `java -jar target/BookLibraryApp.jar` или `mvn javafx:run`.

Результаты и разбор задержки на 851 книге: [замеры запуска](design/startup-analysis.md).

Обложки загружаются в фоне: общая контрастная обложка заменяется изображением книги
по мере готовности. При отсутствии или ошибке чтения файла остаётся общая обложка.

Интерфейс использует светлую шалфейную тему из `design`: компактную шапку,
адаптивную таблицу, формы добавления и редактирования и карточку книги.
Аудиокнопки скрыты согласно спецификации; сохранённые связи остаются в данных.

`Ctrl+N` добавляет книгу, `Ctrl+F` переводит фокус в строку поиска, `Enter`
на выбранной строке открывает карточку. Поиск по названию, автору, издателю,
жанру и циклу работает совместно с применёнными фильтрами. Крестик справа
очищает запрос, сохраняя фильтры. Общий сброс очищает и запрос, и фильтры.
Поиск не зависит от регистра и различия «е»/«ё»; командный синтаксис не используется.
Масштаб таблицы можно менять с помощью Ctrl и колеса мыши.

Подсказки при наведении не повторяют значения полей, таблиц и списков.
Диалоги подтверждения, ошибок и информации оформлены в общей теме приложения,
включая сообщения запуска и самостоятельного помощника обновления.

Кнопка «Фильтры» открывает правую панель. Логические признаки и справочники
выбираются чекбоксами со счётчиками, для чисел доступны диапазоны и сравнения,
для названия — текстовые условия. «Применить» сохраняет настройки, «Отмена»
и Escape отбрасывают черновик. Снизу панели кнопки доступны при любой прокрутке.
Списки значений показывают первые пять вариантов с возможностью раскрытия;
при поиске отображаются все совпадения. Условия отображаются компактными тегами;
стрелка раскрывает остальные строки, кружок рядом показывает число скрытых тегов.
Раскрытие и применённые условия сохраняются при просмотре и изменении книг.
Значения и счётчики фильтров кешируются в фоне при запуске и обновлении каталога;
повторное открытие панели использует готовые данные и существующие элементы.
Параметр запуска `-Dbooklibrary.reducedMotion=true` отключает выезжание панели.

Расширение фильтров описано в `design/windows/filters.md`: метаданные задаются
через `@FilterProperty`, поддерживаемые Java-типы — через `@FilterTypes` на процессоре.
Ядро находится в пакете `filter`: аннотации — `annotation`, условия — `condition`,
модели — `model`, процессоры — `processor`, источники значений — `provider`,
фоновый кеш — `cache`. Реализации процессоров и источников выделены в `impl`.
Панель и теги находятся в `ui.filter`, редакторы — в `ui.filter.editor` и `impl`.
Текстовые условия и поиск внутри списков не зависят от регистра и различия
«е»/«ё»: «СЕМЕН» находит «Семён». Спецсимволы в текстовом условии считаются обычным текстом.

Проверки: `mvn test`. `SageViewsTest` проверяет реальные окна JavaFX и операции
с отдельным временным каталогом, включая компактный режим и защиту черновика.
Для проверки DPI: `mvn -Dtest=SageViewsTest -Dglass.win.uiScale=1.5 test`.
`FilterCatalogTest` проверяет условия, пустые значения, счётчики и регистрацию
новых типов. `NumericFilterProcessorTest` проверяет сравнения и границы чисел,
`FilterOptionCacheTest` — фоновый кеш и обновление после изменения книг.
`-Dbooklibrary.captureFilters=true` сохраняет снимки проверяемого
интерфейса в `target/filters-*.ppm`.

Фильтры обязательных полей не предлагают проверок заполненности. Для цены
«Бесценно» означает отсутствие сохранённой стоимости, а «Подарок» — нулевую цену;
проверка «Стоимость указана» включает ноль. Поиск подстроки цифр удалён.
Русский Javadoc описывает контракты классов и публичных методов фильтров.
[Анализ потоков, памяти и зависимостей кеша](design/filter-cache-analysis.md).

В меню оставлены «Файлы», «Правка» и «Справка». «Экспортировать данные»
предлагает папку и сохраняет ZIP со всеми JSON-файлами из `repository`,
включая вложенные каталоги. «Открыть директорию» открывает папку JAR,
а при запуске из исходников — рабочую папку.

В «Правка» доступны отдельные редакторы циклов, авторов, жанров и публицистов.
Слева находятся поиск и список со счётчиком книг, справа — таблица
«Свойство — Значение». Подписи берутся из `@Property`, тип поля определяет
редактор: строка, чекбокс или целое число. ID доступен только для чтения
и копирования. Под таблицей показаны количество связанных книг и список
названий-ссылок, открывающих карточку книги. После её закрытия черновик
справочника сохраняется, а список и счётчик обновляются.
Сохранение обновляет каталог и фильтры. Удалить запись
можно только при отсутствии связанных книг и после подтверждения.
Неиспользуемые записи теперь сохраняются до ручного удаления.
Окно «О программе» содержит имя Anton Tsel, рукописное «for Jane» и сердечки;
`-Dbooklibrary.reducedMotion=true` также отключает анимацию сердечек.
Согласованный дизайн описан в [спецификации](design/windows/reference-data.md).

«Проверить обновления» проверяет стабильные GitHub Releases, предлагает скачать
новый толстый JAR и установить его после штатного завершения приложения.
При запуске выполняется фоновая проверка: окно появляется только при наличии
новой версии; отсутствие сети не мешает работе.
Отдельный помощник проверяет SHA-256, сохраняет текущий JAR, `repository`
и настройки в `backup/updates` рядом с программой и атомарно заменяет JAR.
После успешной установки новая версия запускается автоматически с прежними
данными и правами исходного приложения. Отмена UAC оставляет приложение
открытым и останавливает подготовленный процесс перезапуска.
Повторный запуск блокируется на время установки; прерванное обновление
можно продолжить при запуске. Права администратора запрашиваются только
при отсутствии доступа на запись. Каталог данных запоминается в
`.booklibrary-data.properties`; явный путь задаётся через
`-Dbooklibrary.dataDirectory=...`. JSON и внешние обложки не перезаписываются.

Базовый [релиз 4.1.0](https://github.com/TselAnton/BookLibrary/releases/tag/v4.1.0)
не содержит автообновления. Первую установку готовой 5.0.0 нужно выполнить
вручную. Выпуск 5.0.0-SNAPSHOT из main запрещён; стабильная 5.0.0 будет
опубликована после завершения разработки. В Actions выберите
`Publish release from selected branch`: main создаёт стабильный релиз,
другие ветки — предварительный. Существующие версии не перезаписываются.
[Механизм, резервные копии и восстановление](design/update-protocol.md).


### JSON-хранилище и версии схем

Данные остаются JSON-массивами и читаются Gson. До создания репозиториев приложение
делает обычную резервную копию, затем применяет схемы из `dao/schema`.
`UserSettings.appliedSchemaVersions` хранит версии по стабильным именам сущностей.
Если версия совпадает с `@StorageEntity.version`, нормализация этого документа
пропускается. Для повторной нормализации после ручной правки JSON нужно закрыть
приложение и уменьшить соответствующую версию в `userSettingsStorage.json`.
Отсутствующая версия считается нулевой; более новая версия блокирует запуск.

Аннотация `@StorageEntity` объединяет стабильное имя схемы, отображаемое имя
`displayName` для сообщений и версию. При изменении формата сущности следует увеличить её версию. Новую сущность нужно
зарегистрировать в `StorageSchemas`. Схема использует сохраняемые поля класса и его
предков; `static`, `transient` и `@Deprecated` исключаются. Неизвестные поля удаляются
при миграции. Имена и прежние имена задаются `@SerializedName(value, alternate)`;
различающиеся значения нового и старого имени считаются ошибкой.
Обязательность задаётся существующей `@Property(nullable = false)`.

`@StorageField(defaultJson = "...")` задаёт JSON-значение по умолчанию.
Для вычисляемых значений используется `provider`, реализующий `DefaultValueProvider`:
он получает `Clock` и возвращает `JsonElement`. Нельзя одновременно задавать provider
и литерал. Отсутствующее поле получает default, если он задан; явный `null` по умолчанию
сохраняется (`KEEP`). Политика `USE_DEFAULT` применяет default также к `null`.
Если default не задан, обязательное пустое поле вызывает ошибку.
Поддерживаются строки, UUID, boolean, int, long, double, списки и карты со строковыми
ключами; новые типы требуют расширения проверки в `EntitySchema`.

У `Book.createdAt` и `Book.updatedAt` задан `CurrentTimeDefault` с `USE_DEFAULT`.
Поэтому старые пустые даты заполняются общей датой миграции через тот же механизм
схемы. Существующие даты сохраняются. Для статистики дата миграции у таких книг
не означает их историческую дату добавления.
При создании книги репозиторий устанавливает даты создания и обновления;
`readUpdatedAt` устанавливается сразу только для прочитанной книги. При дальнейшем
сохранении дата обновления меняется только при изменении данных, а `readUpdatedAt` —
при любом переключении `read`, включая снятие флага. Техническая миграция не обновляет
уже заполненные даты. Обложка и список аудиосайтов входят в сравнение изменений.

Репозитории возвращают и хранят независимые копии объектов. Сохранение книги со
справочниками выполняет `BookSaveService`, удаление аудиосайта со связями —
`AudioBookSiteService`. `RepositoryTransaction` готовит все изменённые документы
до записи и откатывает память при ошибке. `StorageWriteBatch` сохраняет исходные
байты в памяти и восстанавливает затронутые файлы, включая частично записанный.
При неудаче восстановления ошибка содержит исходную причину и ошибки восстановления.
Временные файлы не используются; защита от аварийного завершения процесса или
отключения питания посреди записи нескольких файлов не предоставляется.

Проверка миграции на копии дополнительного набора данных:
`mvn -Dtest=StorageSchemaInitializerTest -Dbooklibrary.schemaFixture=test_data/repository test`.
Исходный набор не изменяется: тест копирует JSON во временный каталог.
